# Выкладка на Cloudflare Pages

Dostyq PDF это статический сайт: после сборки в папке `dist/` лежат только файлы, сервера и
базы нет. Поэтому подходит любой статический хостинг. Ниже порядок для Cloudflare Pages
(бесплатный тариф: 500 сборок в месяц, до 20 000 файлов, до 25 МБ на файл; самый большой файл
проекта, `opencv.js`, весит ~10 МБ).

> Названия пунктов в панели Cloudflare меняются, ищите по смыслу. Cloudflare сейчас советует
> для новых проектов Workers, но Pages не закрыт и продолжает работать.

## Что подготовлено в репозитории

| Файл | Зачем |
| --- | --- |
| `public/_headers` | Заголовки ответов. Копируется в `dist/_headers` при сборке. Год кэша для файлов с хешем в `/assets/`, запрет микрофона и геолокации, камера разрешена только своему сайту |
| `.node-version` | Версия Node для сборки на Cloudflare (`22`) |
| `.env.example` | Единственная необязательная настройка: токен счётчика посещений |

## 1. Создать проект

1. Завести бесплатный аккаунт на cloudflare.com (аккаунты за вас никто не создаёт).
2. Workers & Pages → создать приложение → Pages → подключить Git → выбрать репозиторий.
3. Настройки сборки (пресет «React (Vite)» подходит):

| Поле | Значение |
| --- | --- |
| Production branch | `main` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | пусто (корень репозитория) |

Версию Node Cloudflare возьмёт из `.node-version`. Переменную `NODE_VERSION=22` ставить не
обязательно, но можно, как страховку.

## 2. Первая сборка

Откройте лог первой сборки и проверьте две вещи:

- зависимости установились (в документации Cloudflare не описано, делает ли образ v3
  `npm ci` сам). Если в логе ошибка вроде «cannot find module», поставьте
  Build command `npm ci && npm run build`;
- в конце сборки отработала проверка гигиены бандла (скрипт печатает ошибку только при проблеме).

## 3. Необязательно: счётчик посещений

По умолчанию счётчика нет, и в сборке нет ни его кода, ни запросов к чужим серверам.
Чтобы включить Cloudflare Web Analytics (без cookies):

1. Cloudflare → Web Analytics → добавить сайт → ввести адрес сайта → «Manage site» → JS snippet.
2. В сниппете найти `data-cf-beacon='{"token": "…"}'`, значение `token` скопировать.
3. В проекте Pages → Settings → Variables and Secrets добавить переменную
   `VITE_CF_ANALYTICS_TOKEN` с этим значением для Production (и для Preview, если нужно).
4. Запустить новый деплой: токен подставляется при сборке.

У Cloudflare есть и второй способ, «Enable» на вкладке Metrics проекта Pages: тогда Cloudflare
сам вставляет скрипт при следующем деплое. **Используйте один из двух способов, не оба**, иначе
посещения считаются дважды.

## 4. Проверка после деплоя

Подставьте адрес сайта вместо `<адрес>` (сначала это `<проект>.pages.dev`). Заголовки из
`_headers` локально через `vite preview` не работают, проверить их можно только здесь.

```bash
# файл с хешем в имени: год кэша
curl -sI https://<адрес>/assets/ЛЮБОЙ-ФАЙЛ.js | grep -i cache-control
# главная: Cloudflare по умолчанию просит браузер перепроверять, камера разрешена
curl -sI https://<адрес>/ | grep -iE "cache-control|permissions-policy"
# несуществующий путь: что отдаёт сайт (в документации Cloudflare код 200 не подтверждён)
curl -sI https://<адрес>/net-takoy-stranicy | head -1
```

Ожидается: `public, max-age=31536000, immutable` для файла из `/assets/`; для главной
`public, max-age=0, must-revalidate` и `camera=(self)` в `Permissions-Policy`.

Затем вручную:

- открыть сайт, в консоли браузера нет ошибок;
- загрузить 2–3 фото: `opencv.js` скачивается один раз, при повторном открытии берётся из
  кэша (вкладка Network);
- выключить интернет и открыть сайт заново: работает офлайн;
- установить на главный экран: на iPhone (Safari) через «Поделиться → На экран “Домой”»;
- собрать PDF и сохранить: см. список проверок на телефонах в README.

## 5. Свой поддомен

1. В проекте Pages: Custom domains → добавить `pdf.<ваш-домен>`. **Сначала добавить домен в
   панели**, и только потом создавать запись у DNS-провайдера, иначе сайт отвечает ошибкой 522.
2. У DNS-провайдера создать запись CNAME: `pdf` → `<проект>.pages.dev`. Переносить весь домен
   в Cloudflare для поддомена не нужно.
3. Для основного домена без поддомена (apex) по документации нужно переносить DNS в Cloudflare.

## 6. Обновления

Каждый push в `main` запускает новый деплой. Ветки и pull request получают отдельные адреса для
проверки (Cloudflare добавляет им `X-Robots-Tag: noindex`).

## Что сознательно не настроено

- **Content-Security-Policy.** OpenCV (WebAssembly) требует разрешения на wasm, камеру легко
  сломать неверной политикой, а проверить её можно только на реальном адресе. Если добавлять,
  то сначала в режиме `Content-Security-Policy-Report-Only`. При включённом счётчике нужно
  разрешить скрипт `https://static.cloudflareinsights.com` и соединения с `'self'` и
  `cloudflareinsights.com`.
- **Особый кэш для `opencv.js`.** Имя файла без хеша, а повторные открытия и так закрывает
  кэш service worker; условный запрос браузера стоит копейки. Долгий кэш дал бы риск устаревшего
  файла после обновления.

## Что подтверждено документацией, а что нет

Сверено 19 октября 2026 по документации Cloudflare:

- `_headers`: формат, лимиты (100 правил, 2000 символов в строке), склейка одинаковых
  заголовков из нескольких правил через запятую, значения по умолчанию;
- версия Node (`.node-version`, `.nvmrc`, `NODE_VERSION`; `engines` из `package.json`
  игнорируется), у образа v3 по умолчанию Node 22.16.0;
- без `404.html` Pages работает как одностраничное приложение;
- счётчик без cookies; ручной сниппет работает на сайте без переноса DNS в Cloudflare.

**Не подтверждено, проверяется на реальном деплое:** ставит ли образ v3 зависимости сам;
код ответа 200 для неизвестного пути; поведение переменных `VITE_*` отдельно для Production и
Preview; доступность сайта из Казахстана у операторов (подтверждённых блокировок Cloudflare я не
нашёл, но их никто не измерял).
